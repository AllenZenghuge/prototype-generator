## 1. 测试策略

| 层级 | 类型 | 工具 | 目标 |
|------|------|------|------|
| App 单元测试 | 自动化 | XCTest（CLI 可跑） | 解析结果构建、实况照片合成、任务拆分、权限一致性、工具类 |
| App UI 测试 | 手动 | iOS Simulator / 真机 | 界面渲染、交互流程、勾选与保存 |
| **真机验证** | 手动 | iPhone | **涉及 AVFoundation / PhotoKit / WKWebView 的行为——模拟器覆盖不到** |

> ⚠️ **本项目的特殊之处**：解析依赖 WKWebView、实况照片依赖 AVFoundation + PhotoKit，
> 这两块**模拟器与真机行为不一致**。实况照片这条路上，「模拟器全绿、真机失败」出现过
> 至少三次。**结论：涉及这些模块的改动必须真机验证。**

## 2. 测试环境

| 组件 | 环境 |
|------|------|
| App 编译 | macOS + Xcode（模拟器 iPhone 17，iOS 26.3） |
| 真机 | iPhone（需开启开发者模式，建议用数据线连接） |
| 单测执行 | `xcodebuild ... test -only-testing:MediaExtractorTests` |
| 测试数据 | 三平台的公开内容链接 |

### 单元测试执行命令

```bash
# 模拟器 UDID 会变，先用 xcrun simctl list devices 现查
xcodebuild -project MediaExtractor.xcodeproj -scheme MediaExtractor \
  -destination 'platform=iOS Simulator,id=<UDID>' \
  -parallel-testing-enabled NO test -only-testing:MediaExtractorTests
```

**注意事项**（都是踩过的坑）：
- `-parallel-testing-enabled NO` 必加，否则 Xcode 克隆模拟器实例且常启动失败
- 测试方法**不要用 `@MainActor` 同步标注**——会被静默跳过（输出 `Executed 0 tests` 且状态 passed）
- 末尾的 `** TEST FAILED **` 可能只是 UI 测试 target 启动问题，**看 Test Suite 级别的结果**
- 改了测试文件后若新用例不出现，`clean build-for-testing` 一次（增量编译可能漏）
- 验证要覆盖**全部 target**（`build-for-testing`），只看 App target 会漏掉报错和警告
