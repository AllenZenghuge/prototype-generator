## 2. iOS App 修改

### BUG-003: 下载列表重新下载 — 原任务消失且未重新下载

| 项目 | 说明 |
|------|------|
| **问题** | 点击"重新下载"后记录消失，且未实际下载 |
| **根因** | 原地修改 SwiftData `@Model` 对象时，`persistence.update()` + `loadItems()` 组合导致引用丢失、线程安全等问题，多轮尝试原地修改均失败 |
| **最终方案** | **删旧建新**：重新解析 → `persistence.delete(item)` 删旧记录 → `persistence.insert(newItem)` 建新记录 → `startDownload(newItem)` → `loadItems()` |
| **对应文件** | `ViewModels/DownloadListViewModel.swift` — `retryItem()` 重写；`Services/DownloadManager.swift` — 精简（移除 persistence.update） |
| **修改内容** | 1. `Task { @MainActor }` 保证线程安全<br>2. 解析成功：删除旧记录+旧文件 → 新建记录 → 下载 → 刷新列表<br>3. 解析失败：旧记录标记 `.failed`，不删除<br>4. `startDownload` 不再调用 `persistence.update`，仅修改内存 |
| **影响范围** | DownloadListViewModel + DownloadManager |
| **验证** | ✅ Cmd+R 验证通过，记录正常更新 |

### FEAT-004: 支持小红书、抖音无水印解析

| 项 | 内容 |
|---|---|
| **需求** | 从只支持 X 扩展到三平台 |

### FIX-003: 抖音解析被带到移动分享页，hook 永远等不到响应

| **问题** | 移动 UA 下无论短链还是完整链接，WKWebView 最终都落到 `iesdouyin.com/share/...` 的「打开抖音 App」引导页，该页**不请求 `aweme/detail`** → 25 秒超时 |

### FIX-004: 抖音图文作品（/note/）PC 端不渲染

| **修改内容** | `DouyinWebParser` 实现 `WKNavigationDelegate`，导航中 URL 含 `/note/` 就改写成 `/video/{id}` 重新加载 |

## 4. 图集与实况照片（2026-09）

### FEAT-005: 抖音图集支持下载实况照片

| 项 | 内容 |
|---|---|
| **背景** | 抖音图文作品的每张图都是**实况照片**：静态图 + 一段两三秒的动态片段 |
| **数据来源** | `images[i].url_list`（静态图）/ `images[i].video.bit_rate[0].play_addr`（动态片段） |
| **实现** | `LivePhotoBuilder` 把两个独立文件缝成相册认得的配对资源 |
| **要点 1** | 图片写入 EXIF `MakerApple["17"]`，**标识必须 36 字符 UUID**（ImageIO 会把不足 36 位的用 `.` 补齐，导致配不上） |
| **要点 2** | 静态图**必须转成 JPEG**——抖音给的是 webp，相册不收 webp 做实况照片静态图 |
| **要点 3** | 视频重写需 `com.apple.quicktime.content.identifier` + `still-image-time` 元数据轨，**值是 `0xFF`（-1）不是 `0`** |
| **要点 4** | ⚠️ **音视频必须并行推进**：`AVAssetWriter` 要求各 input 按时间交错，串行会让两个 input 都永远不 ready |
| **要点 5** | ⚠️ **并行时音轨必须用独立的 `AVAssetReader`**：reader 不是线程安全的，共用会竞态 → 合成失败 → 实况照片退化成普通短视频 |
| **放弃的方案** | 自定义 scheme + `AVAssetResourceLoaderDelegate`（播放侧）以 -11849 失败；`Task.detached` 包装合成（真机卡死、macOS 却通过） |
| **验证** | 真机 1 张 / 50 张实况图均成功，长按会动**且有声音**（2026-09-29） |

### FEAT-006: 图集区分「图片 / 视频片段」，可选合并成一个视频

| 项 | 内容 |
|---|---|
| **背景** | 同一作品里可能混着三类内容，此前一律按图片下载 |
| **分类** | `live_photo_type == 1` → 实况照片；`clip_type == 4` → **独立短视频片段**；其余 → 普通静态图 |
| **界面** | 图片页在含视频片段时出现「图片 / 视频」二选一；选「视频」后可选「合并成一个视频」 |
| **合并** | `VideoMerger` 按顺序拼接，画布取最大尺寸、每段等比居中（片段尺寸可能不一致） |
| **踩坑** | `AVMutableComposition` 里留**零样本的音轨**会让导出以 -11849 失败——音轨必须按需创建 |

### FIX-005: 相册保存失败（PHPhotosError 3302）

| **问题** | 图文作品会凭空多出一个「视频」任务，保存到相册必然 3302 |
| **根因** | 图文作品的 `video.play_addr` 是**背景音乐 mp3**（不是封面、不是视频），`video.bit_rate` 为 null 说明没有视频流 |
| **修改内容** | 图文作品（`images` 非空）**不再产出视频任务**；扩展名改用**响应 MIME 优先**判定 |

### FIX-006: 越权读相册导致 TCC 崩溃

| **问题** | 保存实况照片后崩溃，堆栈含 `___TCC_CRASHING_DUE_TO_PRIVACY_VIOLATION___` |
| **根因** | 为「回读校验」调用了 `PHAsset.fetch*`，它需要**读取相册**权限，而 App 只声明了**写入**权限。TCC 遇到越权调用**不会拒绝、不会抛错，而是直接 abort 进程** |
| **修改内容** | 去掉回读校验（配对失败时 `performChanges` 本身会抛错，交给上层走退路即可） |
| **加固** | 新增 `TC-PERM-01`：只声明写入权限时，源码中不得出现 `PHAsset.fetch*` |

### FIX-007: 实况照片保存静默失败 / 无限卡住

| **问题** | 依次出现三种表现：相册里只有图片、没有报错；记录永远停在「下载中」；「合成超时」 |
| **根因 1** | 提取页保存路径漏传 `livePhotoVideoURLs`，`DownloadManager` 查不到动态片段 → 按普通图片存 |
| **根因 2** | 超时用 `withThrowingTaskGroup` 实现，而 TaskGroup 退出前**会等所有子任务**，卡住的任务把超时一起拖死 |
| **修改内容** | 两条保存路径共用 `makeImageDownloadItems`；超时改用**独立看门狗**（到点直接收尾，不等卡住的任务） |

### FIX-008: 重新下载会重下整个图集

| **问题** | ① 视频片段任务点重新下载报「原链接中已无可用媒体」；② 点一张图把整个图集（50 张）重下一遍 |
| **根因** | 图集片段的地址在 `images[i].motionVideoURL`，**不在顶层 `videos` 里**；图片分支取了 `data.images` 全部 |
| **修改内容** | `DownloadItem` 新增 `galleryClipIndex`（记录该项在图集里的序号），重新解析后按序号取回**同一项**；打包任务序号为 nil，仍整体重下 |

## 5. 其他修复（2026-06 ~ 2026-09）

### FEAT-007: v2.0 毛玻璃前端重设计
苹果风毛玻璃 + 悬浮 Tab Bar + 3 Tab 胶囊；`List` 内 Button 需 `.buttonStyle(.borderless)` 否则整行响应点击。

### FEAT-008: 下载前选择保存位置
分「相册」与「文件目录」两条路径；文件目录用 security-scoped bookmark（存 Data 而非 path）。

### FEAT-009: 批量粘贴多链接
`URLParser` 正则提取（分享文案含中文逗号，不能按逗号拆）；自动全量下载；失败链接也写入列表。

### FEAT-010: 视频卡片内播放
点击缩略图在卡片内播放 + 全屏按钮；进全屏时暂停内联播放（避免两个播放器同时出声）。

### FIX-009: 抖音视频播放 403
抖音 CDN 需 `Referer`。AVFoundation 没有给 AVPlayer 设置请求头的公开接口，**先带 Referer 落盘再本地播放**。
（曾试过 `AVAssetResourceLoaderDelegate`，以 -11849 失败，已放弃。）

### FIX-010: 文件名与相册命名统一
文件名 = `博主名_@账号_正文`（链接部分替换为下划线保持可读）；相册用 `originalFilename` 与「文件」App 一致。
