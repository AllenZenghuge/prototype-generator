## 1. 产品定义

### 做什么
iPhone App，粘贴 X / 小红书 / 抖音链接 → 解析提取视频、图片、文案（无水印）→ 保存到相册或「文件」App。下载记录持久保留，可随时重新下载。

### 不做什么
- 不做用户登录/注册
- 不做 iPad 适配
- 不做自动后台批量订阅（批量粘贴解析支持，但不是长期订阅）

### 目标用户
Allen 自己用（日常刷到的内容 → 提取保存），每天几条到几十条。

## 2. 视觉设计：「暗房」

暗房隐喻：从嘈杂、带水印的源中还原出纯净的原始素材，像在暗房里显影底片。

### 色板

| Token | Hex | 用途 |
|-------|-----|------|
| 暗房黑 | `#0d0d12` | 主背景 |
| 阴影灰 | `#16161f` | 次级表面 |
| 水洗灰 | `#1e1e2a` | 卡片/输入框背景 |
| 暗房红 | `#d44a3a` | 唯一强调色，CTA 按钮 |
| 相纸白 | `#f0ebe0` | 主文字（暖调米白） |
| 药水灰 | `#8a8578` | 次文字/辅助元素 |

### 字体

| 角色 | 字体 | Weight |
|------|------|--------|
| 标题/大号 | SF Pro | Medium |
| 正文 | SF Pro | Regular |
| 中文 | 苹方（系统默认）| Regular |

选择系统字体的理由：工具 App 不需要字体性格，精准可靠即可。字重对比（标题 vs 正文的灰度差）比字体选择更重要。

### 标志性元素

**CTA 按钮「显影」动画**（0.8s）：
- 空闲态：暗房红描边圆圈，白色向下箭头
- 点击 → 光晕从中心向外扩散 → 按钮内部由暗变亮 → 界面展开为结果
- 隐喻"相纸在药水里显影"，同时掩盖解析网络延迟


## 4. 各平台解析方案

### 4.1 X (Twitter) — 直连第三方 API

- 调用 `GET https://api.vxtwitter.com/{screen_name}/status/{tweet_id}`
- 从 `media_extended` 提取视频直链、缩略图、图片原图
- 从 `text` / `user_name` / `user_screen_name` 提取正文与作者
- **视频缩略图同时作为 ImageItem 加入 images**（纯视频推文也可单独下载封面）
- 图片取 `format=jpg&name=orig`（原图）
- 需要手机端 VPN

### 4.2 小红书 — 抓 HTML + 正则

- 抓笔记页 HTML，正则提取 `masterUrl`
- ⚠️ `masterUrl` 是 JSON 转义（`\/`）+ HTTP，需 `unescapeJSON` + `normalizeToHTTPS` 才能下载
- 封面优先取 `imageList` 的 `urlDefault`（`og:image` 是平台默认图）
- 无需签名，无需 VPN

### 4.3 抖音 — 隐藏 WKWebView + JS 拦截

**核心思路**：让抖音自己的 JS 去生成 `a_bogus` 签名，App 只负责拦截响应。

流程：
1. 隐藏的 `WKWebView`（1×1，需挂到 window 上才可靠加载）加载链接
2. **必须伪装成桌面 Chrome UA** —— 移动 UA 会被带到 `iesdouyin.com/share/...` 的
   「打开抖音 App」引导页，该页**不请求 `aweme/detail`**，hook 永远等不到响应
3. 注入 JS hook `fetch` / `XMLHttpRequest`，捕获 `aweme/detail` 响应 → `postMessage` 给 Swift
4. 图文作品（`/note/{id}`）在 PC 端不渲染，需改写成 `/video/{id}` 再加载
5. 超时 40 秒；失败时返回**诊断串**（含 WebView 最终停留 URL、页面状态、已发出的 aweme 请求）

**为什么不自建签名**：`a_bogus` 算法自建要 300 行且约两周失效一次；借 JS 签名可自动适配。

## 5. App 设计

### 5.1 技术栈
- SwiftUI + iOS 17+
- `@Observable` 宏（MVVM）
- SwiftData 持久化
- `URLSession` background configuration（后台下载）

### 5.2 数据模型

```
GalleryItemKind（图集项的三种类型）
├── still       普通静态图
├── livePhoto   实况照片：静态图 + 一段两三秒的动态片段
└── videoClip   视频片段：本质是一段独立短视频，只是挂在图集里

VideoItem
├── url: String
├── thumbnail: String?
├── duration: Double?
└── quality: String?

ImageItem
├── url: String
├── width: Int?
├── height: Int?
├── kind: GalleryItemKind        ← 抖音图集靠它区分图/实况/视频片段
└── motionVideoURL: String?      ← 动态片段地址（livePhoto 的伴随片段 / videoClip 的本体）

ParseData（解析响应，一次性消费）
├── platform: String?
├── author: Author?
├── text: String?
├── videos: [VideoItem]?
├── images: [ImageItem]?
└── sourceURL: String?

DownloadItem（SwiftData @Model，持久化）
├── sourceURL / authorName / authorScreenName / authorAvatarURL
├── mediaType: video | image | text
├── title: String                    ← 正文（用作文件名）
├── mediaURLs: [String]              ← 上次解析出的直链（可能过期）
├── livePhotoVideoURLs: [String:String]  ← 图片直链 → 实况照片动态片段
├── mergeVideos: Bool                ← 合并模式：把 mediaURLs 按顺序拼成一个
├── galleryClipIndex: Int?           ← 该项在图集里的序号（重新下载靠它找回同一项）
├── saveToAlbum: Bool                ← 存相册 还是 存「文件」
├── saveDirectoryBookmark: Data?     ← 文件目录的 security-scoped bookmark
├── status: idle → downloading → completed | failed
├── progress / fileLocalPath / errorMessage
└── createdAt / downloadedAt
```

### 5.3 界面

**主界面 (ExtractView)**

三阶段状态机：`idle → parsing → result`

空闲态：
- 输入卡片（水洗灰底、16px 圆角）+ 粘贴按钮
- 暗房红描边圆形箭头按钮（70px，主 CTA）
- 三步引导：分享 → 复制链接 → 提取

解析中：CTA 触发「显影」动画 + "正在解析..."

结果态：
- 三栏 Tab：视频 / 图片 / 文案（`CustomTabBar`，仅显示有内容的栏）
- **视频 Tab**：缩略图 + 质量/时长标签 + 勾选框 + 顶部全选；点击缩略图在卡片内播放（带全屏按钮）
- **图片 Tab**：3 列网格 + 勾选框 + 顶部全选
  - ⚠️ **图集混有视频片段时**，顶部出现「**图片 / 视频**」二选一；选「视频」后可选「**合并成一个视频**」
- 文案 Tab：全文 + "复制文案"
- 底部按钮：保存当前 tab 中勾选的项（先选保存位置：相册 / 文件）

**下载列表 (DownloadListView)**

- 作者头像+名称、链接（点击复制）、状态标签
- 已完成：「重新下载」+「复制链接」；失败：错误原因 + 同上
- ⚠️ **已完成但有说明的也会显示提示**（灰字）——实况照片退回「图片+独立视频」属于降级成功，
  只显示失败原因的话用户不知道拿到的是退路结果
- 左滑删除

### 5.4 下载管理

- `DownloadManager` 单例，`URLSession` background configuration
- 一个 `DownloadItem` 可含多个 URL（图片打包 / 合并视频），**顺序下载**
- 防盗链：抖音 / 小红书 CDN 需带 `Referer` + 桌面 UA（`authorizedRequest`）

**保存策略**：下载 → 临时目录 → 写入相册 **或** 移动到用户选的目录 → 清理临时文件

**实况照片（抖音图集）**：
1. 图集项 `kind == .livePhoto` 时，除静态图外还下载它的动态片段
2. `LivePhotoBuilder` 把两者缝成配对资源：
   - 静态图写入 EXIF `MakerApple["17"]` = 资产标识（**必须是 36 字符 UUID**）
   - 动态片段重写为 mov，写入 `com.apple.quicktime.content.identifier` + `still-image-time` 元数据轨
   - 静态图**必须转成 JPEG**（抖音给的是 webp，相册不收 webp 做实况照片静态图）
3. 存入相册：`addResource(.photo)` + `addResource(.pairedVideo)`
4. 失败退回「静态图 + 独立视频」，素材不丢，原因写进记录

**图集视频片段**：
- 「存视频」模式：每个片段一条任务；「合并」模式：一条任务，下完由 `VideoMerger` 按顺序拼接
- 拼接按最大尺寸建画布、每段等比居中（片段尺寸可能不一致）

**重新下载**：先重新解析拿新鲜直链，再下载（旧直链会过期）。
单张图 / 单个视频片段的任务靠 `galleryClipIndex` 找回**同一项**，避免重下整个图集。

### 5.5 文件命名规则
保存的文件名 = 正文（经 `FilenameSanitizer` 清洗）。多文件时追加序号 `base (1).ext`。

## 6. 错误处理

| 场景 | 表现 |
|------|------|
| 无效 URL | 「请输入有效的链接」 |
| 平台不支持 | 「暂不支持该平台」 |
| 抖音解析失败 | 诊断串（含 WebView 最终 URL + 页面状态），可长按复制 |
| 内容无媒体 | 「原链接中已无可用媒体」 |
| 下载网络错误 | 标记失败，记录原因，可重试 |
| 保存到相册失败 | 记录 `PHPhotosError` 详情，保留临时文件 |
| 实况照片合成失败 | 退回「图片 + 独立视频」，原因写入记录（**不静默**） |
| 相册权限未授权 | 引导前往设置开启 |

### ⚠️ 相册权限：只申请「写入」

`Info.plist` **只有** `NSPhotoLibraryAddUsageDescription`（写入）。
**不要调用 `PHAsset.fetch*`** —— 它需要「读取相册」权限（`NSPhotoLibraryUsageDescription`），
越权调用**不会**被拒绝或抛错，而是被 TCC 直接 `abort` 掉整个进程
（堆栈特征 `___TCC_CRASHING_DUE_TO_PRIVACY_VIOLATION___`）。

已加回归测试 `TC-PERM-01`：只声明写入权限时，源码中不得出现 `PHAsset.fetch*`。
